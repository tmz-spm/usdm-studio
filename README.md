# USDM Studio v1.8.0

USDM Schema 1.1.0 に沿った要求仕様書を、ツリーとフォームで作成するローカルアプリです。

アプリのバージョンは1.8.0、保存する標準文書のスキーマバージョンは従来どおり1.1.0です。以前の標準JSON・プロジェクトJSONをそのまま開けます。

## v1.8：ゲームの流れと詳細仕様をサイクル図で編集

カテゴリ・要求グループ・仕様グループの下に「サイクル図」を追加できます。大まかなゲームの流れをノードと矢印で書き、各ノードの下に詳細仕様や挙動を階層でぶら下げます。分岐や繰り返しを含む流れを扱えます。

1. ツリーまたはツリーグラフで所属先のカテゴリ・グループを選び、右のプロパティの「サイクル図を追加」を押します。「追加」ダイアログからも作成できます。
2. 図の名前を入力すると、その図専用の編集タブが開きます。ツリーグラフのサイクル図ノード、左ツリー、所属先のプロパティから再度開けます。図をいくつ開いても、ツリーグラフは独立したタブとして残ります。
3. 「フェーズ・場面」「行動・処理」「分岐」「開始」「終了」でノードを追加します。ノードをクリックし、右側の「大まかな仕様・場面」に内容を書きます。種類は色と形で区別し、後から変更できます。
4. 「矢印で接続」を押し、遷移元、遷移先の順にクリックします。前の場面へ戻る矢印や、同じノードへ戻る自己ループにも対応します。矢印を選ぶと、右側で条件・きっかけと接続先を編集できます。Escapeで接続操作を中止できます。
5. ノードの「仕様を追加」「挙動を追加」から詳細を書きます。詳細を選択中に追加すると、その詳細の子になります。「ぶら下げる先」で親を変え、「上へ／下へ」で同じ親の中の順序を変更できます。
6. ノードをドラッグして配置します。背景のドラッグで表示位置を変え、Ctrl / Cmd＋ホイールで拡大縮小できます。「全体表示」で図全体を収めます。
7. 「プロジェクト保存」で、要求・仕様とすべてのサイクル図を同じJSONへ保存します。

図のタブの「×」は編集タブだけを閉じます。図を削除する場合は右のプロパティで図名を選び、「この図を削除」を使います。ノード・詳細・図の削除は対象範囲を確認して実行し、元に戻す・やり直すにも対応します。上部や左右パネルの表示調整も引き続き使えます。

所属グループの移動・並べ替え・複製にはサイクル図も追従します。図自体の所属先は、図名を選んで右の「所属グループ」で変更できます。グループの削除や種類変更で図が失われる場合は確認画面に表示します。「選択ノードだけ削除」では図も残す子として扱い、親へ直接つなげられない場合は禁止します。

サイクル図を含むファイルはプロジェクト形式2で保存します。標準USDM文書の外側に図を保持するため、公開スキーマは変更していません。図がない文書は従来のプロジェクト形式1で保存します。形式2はv1.8以降で開いてください。文書プレビュー・印刷には、図のノードの内容、詳細仕様・挙動、遷移の表を含めます。

## v1.7.1：空の文書から開始

起動時は要求・仕様のない空の文書を表示します。USDMスキーマで必須のカテゴリ「＜機能要求＞」だけを用意し、そのまま要求を追加できます。サンプル文書はアプリ・配布物に含めません。

前回の一時保存がある場合は「復元する」または「空の文書から開始」を選べます。空の文書を表示しただけでは、前回の一時保存を上書きしません。

「挿入」およびグラフの枝の「＋」では、直後への挿入を初期選択にします。必要に応じて直前への挿入も選べます。

## v1.7：表示領域の調整

プロジェクト名の下に説明（metadata.description）を常時表示しないようにしました。タイトル横の「説明」から必要なときに開けます。説明の編集は「文書設定」から行います。文書プレビュー・印刷には引き続き説明が含まれます。

編集ツールバーの「表示」で、左のエクスプローラー・右のプロパティ・上部を、それぞれ「標準」「小型」「非表示」に切り替えられます。「編集領域を最大化」で3か所をまとめて隠し、「標準に戻す」で元の表示へ戻せます。

- 左右のパネルは、見出しまたはツールバーのアイコンでも開閉できます。再表示すると直前の標準・小型の幅に戻ります。
- 上部のアイコンは標準 → 小型 → 非表示の順に切り替わります。上部を隠してもモードのタブ、開く・保存、表示操作は残ります。
- 表示の切り替えでは、入力途中のプロパティ・未適用のJSON・一括ラベルの入力や選択を保持します。
- 表示設定はブラウザに記憶します。プロジェクトJSONや文書の更新日時には影響しません。ブラウザ設定やHTMLの移動により、記憶した設定を利用できなくなる場合があります。

## v1.6：削除方法とノード種類の変更

### 子を残して選択ノードだけを削除

削除ダイアログの「削除方法」で選択できます。

- **子孫もすべて削除**：従来どおり、選択したノードとその配下を削除します。
- **選択ノードだけ削除し、残す子をその親へ直接つなぐ**：選択したノード本体だけを除去し、残す子を元の親へつなぎ直します。子の種類・内容・ID・自由ラベルは変更しません。複数選択では、明示的に選択したノードだけを取り除きます。

直接つないだ結果がUSDMスキーマに違反する場合は、削除ボタンを無効にして理由を表示します。子の移動先・種類を勝手に変更したり、未選択の空グループを追加で消したりしません。

例えば「要求 → 仕様グループ → 仕様」から仕様グループだけを削除すると、「要求 → 仕様」という不適合な構造になるため禁止します。「要求 → 要求グループ → 下位要求 → 仕様グループ」の中間の要求グループと下位要求をすべて選択して削除すると、「要求 → 仕様グループ」という有効な構造に戻せます。

削除対象の自由ラベルと、削除した要求・仕様グループを参照する関連は取り除きます。残した子の参照は維持します。元に戻す操作で削除前に復元できます。

### ノードの種類を変更

右側のプロパティの「種類」から変更します。文書を除くカテゴリ・要求・要求グループ・下位要求・仕様グループ・仕様が対象です。

1. 変更後の種類を選びます。
2. 変更後の所属先を選びます。新しい種類を現在の親に置けない場合、適合する既存の所属先、または必要な親階層を新規作成する配置を選べます。
3. 確認画面で、引き継がない項目、削除される子孫・空になる元のグループ・自由ラベル・関連、新しく作る階層、IDの変更を確認します。
4. 「警告を確認して種類を変更」を押して反映します。キャンセル・Escapeでは文書を変更しません。

要求本文と仕様本文は相互に引き継ぎます。理由・説明・ID・キーワード・仕様ラベル・子配列は、変更先にも同じ項目がある場合に保持します。自由ラベルは変換するノードに引き継ぎます。要求のキーワードを仕様へ、仕様のチェックを要求へ引き継ぐことはできず、実行前に削除対象として表示します。変更先で使えないIDは重複しない形式へ再生成します。

元の所属先に必須の子がなくなる場合、種類変更では空になるグループを整理することがあります。これも削除一覧に表示します。これは上記の「子を残して削除」とは別の処理で、種類変更の確認後にのみ行います。

追加・挿入のダイアログの「基準：」表記は「操作対象の階層：」に変更しました。文書間の変更比較では、比較ファイルを「比較元：」と表示します。

## v1.5で追加した機能

### レビュー支援

「レビュー」タブで、理由の未記入、仕様のない要求、追加時の初期文言、未定・要確認・TODO/TBD、同じ種類で重複する本文、関連の参照先、仕様のチェック順を確認できます。未レビュー仕様の一覧とレビュー済み件数も表示します。

一覧をクリックすると右のプロパティで編集できます。「グラフで表示」で対象へ移動し、「表示中の要素を一括選択」でラベルや仕様チェックをまとめて変更できます。画面は先頭200件まで表示し、「一覧を保存」で全件をJSONに出力します。検索・ラベル絞り込みは一覧にも反映されます。

これらはルールによる確認候補です。内容の正しさや要件の完全性を自動判定する機能ではありません。単一の下位要求については、強制2層の記法に合わせて理由の未記入を指摘しません。

### 変更比較

「変更比較」で過去の標準JSON・プロジェクトJSONを基準として開くか、「現在の文書を基準にする」を押してから編集してください。現在の文書を置き換えず、追加・削除・内容変更・所属変更・順序変更を確認できます。本文、理由、説明、キーワード、仕様ラベル、自由ラベル、文書情報、関連の変更を比較し、差分をJSONに出力できます。

- 要求・下位要求・仕様は種類とIDで照合します。IDを変えた場合は削除と追加になります。
- IDのないカテゴリ・グループは、親、種類、名前、同名内の順番で照合します。改名や移動は追加・削除になる場合があります。同名グループの厳密な同一性判定はできません。
- 更新日時、アプリ内の一時識別子、JSONオブジェクトのプロパティ順序は比較しません。途中への新規挿入による単なるインデックス変化も、既存要素の順序変更としては扱いません。
- 比較基準はこの画面内で保持する一時的なものです。プロジェクト保存やブラウザの一時保存には含まれません。新規作成・別文書の読み込み・再読み込みで解除されます。永続的な基準はJSONファイルで保管してください。
- 画面は先頭200件まで表示し、「差分を保存」で全件を取得できます。

### 要素の複製

要素を選び「複製」を押すと、子要素を含めて直後へ複製します。複数選択にも対応します。IDには `_copy` などの接尾辞を付けて重複を防ぎ、カテゴリ・グループ名も一意にします。キーワードと自由ラベルを引き継ぎ、仕様のチェックは初期設定では未レビューへ戻します。複製ダイアログでチェックを維持することもできます。関連配列は複製しません。

### 検索と編集操作

- **Ctrl / Cmd + K** または上部の「検索 / 移動」：ID、本文、理由、ラベルから要素を検索。完全一致のIDを優先し、↑↓とEnterで移動します。
- **Ctrl / Cmd + Enter**：プロパティの変更を適用。JSON編集中はJSONを検証して適用します。
- **プロパティの「取り消す」**：未適用の入力だけを元に戻します。適用済みの変更は「元に戻す」で戻します。
- **プロパティの階層名**：親へ直接移動できます。
- **グラフの「選択を中央へ」**：必要な祖先を展開し、絞り込みを解除して、選択要素を読みやすい倍率で中央へ移動します。
- グラフで検索・ラベル絞り込みが残っている場合は画面上部に表示し、その場で解除できます。
- 編集ボタンを右ペインの下部に固定し、長い本文でも適用・取り消しへアクセスしやすくしました。

## 起動

同梱の `USDM-Studio.html` をダブルクリックし、Chrome または Edge で開いてください。Windowsでは `Start.cmd` からも起動できます。
GitHubまたは配布ZIPから取得した場合は、ZIPを展開してからフォルダー内の `USDM-Studio.html` を開きます。開発時のビルド結果は `dist/USDM-Studio.html` に出力します。
アプリ実行時のインストール・サーバー・ネット接続は不要です。初回は空の文書が表示されます。

## 基本操作

1. 「新規」で文書を作るか、「開く」で既存のJSONを読み込みます。
2. 左のツリーで要素を選択します。中央はその範囲の内容、右側はプロパティを表示します。「文書全体」で全体表示に戻れます。
3. 右側でID、要求・仕様、理由、説明、ラベルを編集し、「変更を適用」を押します。要素の切り替え時にも適用します。検証に失敗した入力は適用されません。
4. 「追加」で子要素、「挿入」で同じ種類の要素を直前・直後へ追加します。必須の子を持つグループには初期要素を同時作成します。
5. 「移動」で親を変更し、上下ボタンで同じ階層の順序を変更します。ドラッグ先の上1/4は直前、中央は子、下1/4は直後です。
6. チェックボックス、Ctrl / Cmd + クリック、Shift + クリックで複数選択できます。右側で共通ラベルを追加・除去し、仕様のレビュー・実装・テストのチェックも一括変更できます。選んだ要素だけが対象です。
7. 「プロジェクト保存」で作業一式をJSONとしてダウンロードします。

カテゴリ → 要求 → 仕様グループ → 仕様、および要求 → 要求グループ → 下位要求 → 仕様グループ → 仕様に対応しています。1つの要求に両パターンを共存できます。

## ツリーグラフ

「ツリーグラフ」タブで、JSONの親子構造をノードと枝として表示します。要求間・仕様グループ間の関連配列は引き続き「関連」タブで扱います。

- **クリック**：右側のプロパティで、そのノードの内容を編集します。Ctrl / Cmd / Shiftで複数選択し、一括ラベル操作もできます。
- **枝へドラッグ＆ドロップ**：枝の先のノードの直前へ、同じ種類の既存ノードを移動します。別の親からの移動も可能です。枝の線と「＋」のどちらにもドロップできます。
- **ノードへドロップ**：そのノードの子として末尾へ移動します。
- **枝の「＋」**：同じ親の下で、枝の先の要素の直前・直後に新しいノードを挿入します。初期選択は直後です。
- **要求 → 仕様グループの枝の「＋」**：「間に下位要求を挿入」を選ぶと、要求グループと下位要求を作り、既存の仕様グループ全体を下位要求の下へ移します。既存の仕様・ID・ラベルは維持されます。中間に別の階層を挟めない枝は、同じ階層への挿入になります。
- **色・形**：文書は濃色、カテゴリは黄色の丸型、要求は緑の角丸、下位要求は水色の破線、グループはフォルダー型、仕様は紫の四角です。種類名も常時表示します。
- **表示操作**：背景をドラッグしてパン、Ctrl / Cmd＋ホイールで拡大縮小。「全体を収める」「100%」「選択範囲」で表示範囲を調整します。各ノードの「− / ＋」で子孫を折りたたみ・展開できます。
- **画面幅**：「表示領域を広げる」で左のエクスプローラーを隠し、「ツリーを表示」で戻せます。全モード共通の表示設定と連動します。右のプロパティや上部も、編集ツールバーの「表示」から小型化・非表示にできます。ノードの全文は右のプロパティで確認できます。

移動先が適切なら緑、不適切なら赤で表示します。階層の制約、必須の子要素、自己・子孫への移動は検証され、無効な操作は文書を変更しません。グラフ操作も元に戻す・やり直すとJSON保存の対象です。

## 保存形式

| ボタン | ファイル | 保存内容 |
| --- | --- | --- |
| プロジェクト保存 | `文書名.usdm-project.json` | スキーマ準拠文書、自由ラベル、サイクル図とその詳細仕様・挙動 |
| USDM JSON | `文書名.usdm.json` | スキーマ準拠の標準USDM文書のみ |

どちらも「開く」で読み込めます。ファイルはブラウザのダウンロード先に保存されます。既存ファイルへの自動上書きは行いません。

**サイクル図を保存する場合は「プロジェクト保存」を使用してください。** 「USDM JSON」は標準文書だけを出力するため、サイクル図とその詳細仕様・挙動は含めません。図がある状態で実行すると、除外されることを確認してから出力します。

標準の **キーワードラベル** は要求・下位要求の `keywords` に保存します。**仕様ラベル** は仕様の `verified` の3つの真偽値です。
任意の **自由ラベル** は、スキーマが許可しないプロパティを標準文書へ混入させないため、プロジェクト形式の `labels` に保存します。外部ツールへ渡す標準JSONには自由ラベルは含みません。
フォームでラベルを新規入力する場合はカンマ区切りです。カンマや改行そのものを含むキーワードはJSON編集で記述できます。

サイクル図を含むプロジェクト形式の例：

```json
{
  "format": "usdm-studio-project",
  "projectVersion": 2,
  "document": {
    "version": "1.1.0",
    "title": "要求仕様書",
    "categories": [{"name": "＜機能要求＞", "requirements": []}]
  },
  "labels": {"/categories/0": ["リリース1"]},
  "cycleDiagrams": {
    "/categories/0": [{
      "id": "cycle_match",
      "title": "対戦の流れ",
      "description": "",
      "nodes": [],
      "edges": []
    }]
  }
}
```

`labels` と `cycleDiagrams` のキーは `document` を起点とするJSON Pointerです。GUI上の移動・並べ替え時には、ラベルと図も対象要素に追従し、保存時にパスを再生成します。図には `id`・`title`・`description`・`nodes`・`edges` を保存します。ノードは `id`・`kind`・`text`・`description`・`x`・`y`・`details`、矢印は `id`・`source`・`target`・`label` を持ちます。詳細は `id`・`kind`・`text`・`children` を持ち、`children` にさらに詳細を追加できます。

ノードの `kind` は `phase`・`action`・`decision`・`start`・`end`、詳細の `kind` は `specification`・`behavior` です。サイクル図のないプロジェクトでは `projectVersion` は1となり、`cycleDiagrams` は出力しません。

## JSON編集・検証

- 「JSON 編集」では、サイクル図がある場合はプロジェクトJSON全体、ない場合は標準文書を表示します。「JSONを検証して適用」で反映します。不正なJSONや図の壊れた接続は現在の文書を変更しません。
- 標準文書だけを貼り付けて適用した場合、自由ラベルとサイクル図は、要素のIDまたは種類と一意な名前が一致する所属先へ引き継ぎます。JSON上の改名・削除などで同定できなくなったラベル・図は、確認後にのみ除去します。GUIでの変更なら内部識別子が維持されます。
- 公開Draft-07スキーマの原本をAjvで検証します。必須フィールド、型、グループ名、要求IDの形式、配列の最小要素数、追加プロパティ禁止などをチェックします。文書内のID重複も拒否します。
- 最後のカテゴリ、要求グループ内の最後の下位要求、仕様グループ内の最後の仕様は、単独では削除・移動できません。親グループ全体を操作するか、先に代わりの子要素を追加してください。
- 存在しない参照先、同名グループへの曖昧な関連、下位要求が1つの場合の理由・説明は「検証」で注意として表示します。外部参照や既存内容を勝手に削除しません。
- GUIで要求ID・一意な仕様グループ名を変更すると関連の参照先も更新します。要素を削除すると対象への関連も取り除き、元に戻す操作で復元できます。
- 「関連」で要求間・仕様グループ間の関連を追加・削除できます。既存関連の直接変更はJSON編集でも可能です。

## 作業の保全

- 最大100操作の取り消し・やり直しに対応します。新規作成・別ファイルの読み込み時には履歴をリセットします。
- ブラウザ内にも適用済みの作業を一時保存します。再度開くと復元を選べます。一時保存できない場合は画面下部に表示します。
- 一時保存は1文書分です。ブラウザ設定、プライベートモード、HTMLの移動などで利用できなくなる場合があります。未適用のフォーム・JSON編集は一時保存に含まれません。重要な変更はプロジェクトJSONとして保存してください。
- 未保存の変更がある状態でのページ終了時にはブラウザの確認を求めます。
- 20MB以下のJSONファイルを読み込めます。共同編集・クラウド同期には対応していません。

## 開発とテスト

Node.js 22以降とnpmを使用します。依存パッケージの初回取得時のみネット接続が必要です。

```powershell
npm ci
npm run build
npm test
node tests/browser.mjs
node tests/graph-browser.mjs
node tests/v15-browser.mjs
node tests/v16-browser.mjs
node tests/v17-browser.mjs
node tests/cycles-browser.mjs
node package-release.mjs
```

最後のGUIテストにはインストール済みのGoogle Chromeが必要です。
v1.8ではモデル44件・GUI73件の計117件を確認しています。サイクル図の保存・復元、詳細の階層編集、条件付き矢印、配置変更、タブ、JSON編集、削除と取り消しを含みます。
`src/` がUI・モデル、`schema/` が原本、`tests/` が回帰テスト、`dist/` が実行ファイルです。
ブラウザテストの結果は `test-results/browser/` に出力します。予約管理の検証データは `tests/fixture.mjs` から明示的に読み込み、アプリの初期文書には使用しません。全テストの実行後、`package-release.mjs` で配布用の説明書・ライセンス・検証結果を `dist/` に揃えられます。
ビルド結果は依存ライブラリ・CSS・スキーマを含む単一HTMLで、実行時に外部リソースを読み込みません。
